Hello from swift-pwa

A system webview (WKWebView / WebKitGTK / WebView2) driven from Swift, with the __SWIFT_PWA__ bridge wired up at document start.

Shortcuts: ⌘R rename · ⌘1 800×600 · ⌘2 1024×768 · ⌘T server time · ⇧⌘C copy title · ⇧⌘V paste · ⌘K clear log

Window

Title and size go through WindowPlugin's main-actor-hopping invokes.

Bridge

Round-trip a JSON envelope through BridgeRuntime — minimal proof the dispatcher is alive.

Clipboard

Reads and writes via the host's pasteboard: NSPasteboard on macOS, UIPasteboard on iOS, GdkClipboard on Linux, the Win32 Clipboard API on Windows.

Tray

System tray icon plus popup menu. iOS and the GTK4 backend log a one-shot warning instead — no system tray on iOS, and libayatana-appindicator3 can't be reused from a GTK4 process.

Dialogs

Native message / confirm / file pickers via DialogPlugin. Each backend wires its platform's HIG dialog: NSAlert / NSOpenPanel on macOS, UIAlertController / UIDocumentPickerViewController on iOS, GtkMessageDialog / GtkFileChooser on Linux, MessageBoxW / IFileOpenDialog on Windows.

Filesystem

Round-trip a scratch file via FsPlugin: fs.writeText, fs.readText, fs.metadata, fs.remove. Path comes back from dialog.saveFile / picks a temp file when cancelled. Foundation-backed, same surface on every host.

Content packs

The runtime content-pack flow: extract a .zip natively (fs.extractZip, bytes never cross the bridge) into the app's data dir, then reference the extracted media by an origin-relative URL served via ctx.serveDirectory("/packs") — same code on every backend, streamed with HTTP range requests. The sample pack is staged to a real path by a small demo.stageSamplePack command (standing in for dialog.openFile).

Import pack exercises the real flow: dialog.openFile → fs.listZip / fs.extractZip on the picked archive. On Android the pick is a content:// SAF URI fed straight to the zip ops (read off-bridge via the ContentResolver); on desktop it's a real path. Pick any .zip.

Biometrics

Cross-platform biometric.canAuthenticate + biometric.authenticate. Touch ID / Face ID / Optic ID on Apple, Windows Hello on Windows, stub on Linux (no clean cross-distro primitive).

Updater

Cross-platform updater.check + updater.run + updater.installAndRelaunch. The demo wires a synthetic DemoUpdater (defined in HelloPWA.swift) so you can see the streaming progress bar fill without a real release server. Production apps swap in AppleUpdater / LinuxAppImageUpdater / WindowsUpdater pointed at a signed manifest.

Notifications

Cross-platform notifications.send. On Windows the second button names what it's exercising: look for the toast in Action Center attributed to SwiftPWA.HelloPWA (the AUMID derived from the exe basename). If the WinRT path failed, stderr will say so and the message came from the Shell_NotifyIconW balloon fallback. On macOS / Linux both buttons just send a regular notification.
